# Audit: dshap474/jarvis

Проверено: 2026-09-24. Источник: `https://github.com/dshap474/jarvis`.

## Классификация: ADAPT, не устанавливать

Репозиторий предлагает локальное рабочее пространство для Codex/Claude с долговременной памятью, Skills и реестром инструментов. Он функционально пересекается со Studio OS MASTER, MARK Project Memory, Knowledge Base и нашим plugin layer.

## Проверка

| Область | Результат |
|---|---|
| Актуальность | Ранний публичный scaffold, один commit, без releases. |
| Лицензия | LICENSE в корне не обнаружен. Копирование и распространение кода или Skills не разрешаем. |
| SKILL.md | Есть набор workflows для intake, source notes, wiki, GitHub, YouTube и X. Не импортируем из-за лицензии и дублирования. |
| Scripts/tools | `_tools` запускает внешние локальные инструменты и загружает отдельные `.env`; возможны сеть, OAuth, сообщения и медиасервисы. Требует отдельного аудита каждого инструмента. |
| Dependencies | Проект предписывает `uv` и `bun`; конкретные инструменты имеют собственные зависимости. Для Studio OS это лишний параллельный runtime. |
| Permissions | В tool index присутствуют браузер, GitHub, Google Workspace, Discord, Telegram, WhatsApp, Messages, Spotify и posting в X. Эти полномочия слишком широки для импорта целиком. |
| Дублирование | Высокое: AGENTS.md, Skills, filesystem memory и tool routing уже реализованы в Studio OS. |
| Совместимость | Концептуально совместим; прямое объединение создаст второй источник правил и конфликт каталогов. |

## Что адаптировано

Только общий принцип разделения знаний:

1. `local/knowledge/inbox` — необработанные входящие материалы.
2. `local/knowledge/sources` — точные заметки по отдельным источникам.
3. `local/knowledge/wiki` — проверенный синтез по нескольким источникам.

Реализация написана для Studio OS заново. Она не копирует чужие Skills, scripts или формулировки. Project Memory остаётся центральным состоянием проектов и не заменяется Knowledge Base.

## Итог

Полный проект: **SKIP**. Архитектурный принцип knowledge intake: **ADAPT**. Повторный аудит имеет смысл после появления лицензии, releases, истории изменений и тестов.
